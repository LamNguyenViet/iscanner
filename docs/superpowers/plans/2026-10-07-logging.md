# System Log Files Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- Errors, warnings and key events are written as JSON Lines to `logs/YYYY-MM-DD.log` (local day, app-private).
- Files older than 7 days are deleted on start.
- No file or image content (bytes, base64, data URIs) ever reaches a log.
- Users can send their logs from Settings.

**Architecture:**
- Pure modules in `src/logging/`: `redact`, `format`, `retention`.
- `logger.ts` is a buffered writer over `FsAdapter`, extended with `list` and `append`. It exports an app singleton `log` over `expoFs`.
- Wiring:
  - `app/_layout.tsx`: init, retention, `app.start`, global handlers, flush on background.
  - `useErrorAlert` logs every shown error.
  - Silent catches and `console.warn` become `log.warn`.
  - Key events become `log.info`.
- Settings gets a "Send error logs" row that exports and shares the logs.

**Tech Stack:** Expo SDK 57 (`expo-file-system` `File`/`Directory`/`Paths`, `File#write(text, { append: true })`, `expo-sharing`, `expo-constants`), RN 0.86 (`ErrorUtils`, `AppState`), TypeScript, Jest + RNTL v14 (async `render`/`fireEvent`/`act`).

**Spec:** `docs/superpowers/specs/2026-10-07-logging-design.md` (§2 for exact shapes and rules; §3 for edge cases).

## Global Constraints

- **Log file:** `Paths.document/logs/YYYY-MM-DD.log`, named by local date, in JSON Lines (one record per line, ending in `\n`).
- **Record keys:** `t` (local ISO with offset, e.g. `2026-10-07T19:35:12.481+07:00`), `lvl` (`debug|info|warn|error|fatal`), and optionally `code`, `event`, `msg`, `file`, `data`, `cause`, `app`, `os`. `app`/`os` appear only on `error`/`fatal` records and on `app.start`.
- **Redaction:** every written record passes through `redact`:
  - any typed array or `ArrayBuffer`/`Buffer` → `"[binary N bytes]"`;
  - a data URI with `;base64,` → `"[data-uri <mime|unknown>, N chars]"`;
  - a string of ≥ 200 characters made only of `[A-Za-z0-9+/=\r\n]` → `"[base64 N chars]"`;
  - any other string longer than 2,000 characters → truncated with `…[+N chars]`;
  - depth > 5 → `"[depth]"`;
  - arrays longer than 50 → the first 50 plus `"[+N items]"`;
  - circular references → `"[circular]"`;
  - functions and symbols are dropped;
  - an `Error` → `{ name, message, code?, fileName?, stack (≤ 20 lines), cause (≤ 3 levels) }`.
- **Retention:** keep today plus the 6 previous days. Ignore names that are not `YYYY-MM-DD.log`. Keep files with future dates.
- **Logger behaviour:**
  - flush every 2 s; `error`/`fatal` flush immediately;
  - the buffer cap is 500 records, and on overflow the next write records a `warn` with `{dropped:N}`;
  - the daily cap is 2 MB, after which only `warn`/`error`/`fatal` are written;
  - `debug` goes only to the console, and only in dev;
  - the logger never throws.
- **No `console.*`** in `app/` or `src/` outside `src/logging/`.
- **Copy:** all copy lives in `src/i18n/`. The no-hard-coded-Vietnamese guard must stay green. New keys:
  - vi: `settings.support: 'Hỗ trợ'`, `settings.sendLogs: 'Gửi log lỗi'`, `settings.noLogs: 'Chưa có log nào.'`;
  - en: `'Support'`, `'Send error logs'`, `'No logs yet.'`.
- **Version:** 1.6.0, `android.versionCode` 6, `ios.buildNumber` "6".
- **Checks:** `npm test` and `npm run typecheck` pass at the end of every task.
- **Do not touch:** `.gitignore`, `.claude/`, `docs/claude-memory/`, `requirement/`, `New folder/`, `ios/`, `android/`.

## Review Focus

1. **A record carrying image data in an unexpected place**, for example inside an error's `cause`, a nested `data` field, or an array of buffers. Expected: no base64 run and no `data:` prefix in the file. Pinned in Task 1 (the redact property test) and Task 2 (a file-level assertion after real logger writes).
2. **The fs write fails, or `list` throws during retention.** Expected: no exception escapes and the app continues. Pinned in Task 2.
3. **A crash, i.e. an uncaught JS error.** Expected: a `fatal` line with the stack reaches the file before the previous handler runs. Pinned in Task 2 (the handler test with an awaited flush order).
4. **The day changes while the app is open.** Expected: the next flush appends to the new day's file. Pinned in Task 2 (inject `now`).
5. **Sending logs when no log file exists yet, or when sharing fails.** Expected: a "No logs yet" notice, or a `SHARE` popup, with no crash. Pinned in Task 4.

### Task 2: Logger, fs adapter, global handlers

**Files:**
- Create: `src/logging/logger.ts`, `src/logging/globalHandlers.ts`

- Test: `__tests__/logging/logger.test.ts`, `__tests__/logging/globalHandlers.test.ts`, `__tests__/library/memoryFs.test.ts` (or the existing fs tests)

**Interfaces:**
- Consumes: the Task 1 functions.
- Produces:
  - `type Logger` (spec §2.4, with `init(meta: { app: string; os: string }): Promise<void>`, `flush(): Promise<void>`, and `debug/info/warn/error/fatal`);
  - `createLogger(deps: { fs: FsAdapter; now?: () => Date; console?: Pick<Console,'log'|'warn'|'error'>; dev?: boolean; dir?: string /* default 'logs' */ }): Logger`;
  - `export const log: Logger` (singleton over `expoFs`, `dev: __DEV__`);
  - `installGlobalHandlers(logger: Logger, deps?: { errorUtils?: …; tracker?: … }): () => void`. This wraps `ErrorUtils.getGlobalHandler()`: it logs `fatal`, awaits `logger.flush()` (bounded, never blocking more than one tick if flush hangs: race with `Promise.resolve()` after a 500 ms timeout), then calls the previous handler. When available it enables Hermes promise-rejection tracking (`global.HermesInternal?.enablePromiseRejectionTracker`), and an unhandled rejection becomes `logger.error('UNHANDLED_REJECTION', msg, { cause })`. It returns an uninstall function.
- Record shapes:
  - `error(code, msg, {file, cause, data})` → `{t, lvl:'error', code, msg, file?, cause?, data?, app, os}`;
  - `info(event, data)` → `{t, lvl:'info', event, data?}`;
  - `warn(msg, data)` → `{t, lvl:'warn', msg, data?}`.

  - `error` is written without advancing timers, and carries `app`/`os` after `init`.
  - Two records in one flush → one append of two lines, in order.
  - **Day change (Review Focus 4):** move `now` to the next day, log, flush → the line lands in the next day's file.

Choose one and test it.

### Task 4: Export logs from Settings

**Files:**
- Create: `src/logging/exportLogs.ts`, `src/native/shareLogs.ts`
- Modify: `app/settings.tsx`, `src/i18n/vi.ts`, `src/i18n/en.ts` (the three keys in Global Constraints)
- Test: `__tests__/logging/exportLogs.test.ts`, `__tests__/native/shareLogs.test.ts`, `__tests__/app/settings.test.tsx`

**Interfaces:**
- `exportLogs(deps: { fs: FsAdapter; logger: Pick<Logger,'flush'>; now?: () => Date; meta: { app: string; os: string; language: string }; writeExport: (name: string, text: string) => Promise<string /* uri */> }): Promise<{ uri: string; files: number; bytes: number } | null>`.
  - It flushes, then lists `logs/`, keeping only valid `YYYY-MM-DD.log` names sorted ascending.
  - When there are none it returns `null`.
  - Otherwise the text is a header line `iScanner <app> · <os> · <language> · <localIsoTimestamp(now)>`, a blank line, then for each file `=== <name> ===` followed by its content.
  - It writes via `writeExport('iScanner-logs-<YYYY-MM-DD>.txt', text)` and returns `{ uri, files, bytes }`.
- `src/native/shareLogs.ts`:
  - `writeLogExport(name, text): Promise<string>` writes to `Paths.cache` and returns the `file://` uri;
  - `shareLogFile(uri): Promise<void>` calls `Sharing.shareAsync(uri, { mimeType: 'text/plain', UTI: 'public.plain-text' })`, and any failure throws `ShareError({ cause })`.
- **Settings:**
  - a third group `t.settings.support` with a row `t.settings.sendLogs` (`accessibilityRole="button"`, disabled while working);
  - on press: `exportLogs`, then either `Alert.alert(t.settings.noLogs)` for `null`, or `shareLogFile(uri)` followed by `log.info('logs.exported', {files, bytes})`;
  - errors go to `showError`.
