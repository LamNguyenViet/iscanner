# Typed Errors and Localized Error Popups — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** every user-facing error is a named `AppError` subclass with a stable code. It is shown through one `showError()` as a localized popup (title, message, and the line `Mã lỗi: CODE` / `Error code: CODE`).

**Architecture:**
- `src/errors/AppError.ts` (classes + `toAppError`) and `src/errors/messages.ts` (`errorContent`/`errorsContent` over `t.errors`) are pure.
- `src/errors/useErrorAlert.ts` is the single display point; part 4 will hook logging there.
- Producers throw or return typed errors. Screens call `showError`.

**Tech Stack:** Expo SDK 57, RN 0.86, TypeScript, Jest + RNTL v14 (async `render`/`fireEvent`/`act`). The i18n tables from part 2 are `src/i18n/vi.ts` (`Strings = typeof vi`) and `src/i18n/en.ts`; `useLocale()` comes from `src/i18n/LocaleContext.tsx`.

**Spec:** `docs/superpowers/specs/2026-10-07-errors-design.md`. §2 holds the full catalogue with the exact copy; the briefs refer to it instead of repeating it.

## Global Constraints

- **Copy:** use the exact vi/en copy from spec §2: titles, messages, short reasons, and the code line (`Mã lỗi: ${code}` / `Error code: ${code}`). The `PDF_LOAD` message must be exactly:
  - vi: `Không load được file, vui lòng kiểm tra lại định dạng file PDF.`
  - en: `Cannot load file, check your document's format file PDF.`
- **Error codes:** exactly these 11: `PDF_LOAD`, `PDF_ENCRYPTED`, `FILE_TOO_LARGE`, `FILE_UNSUPPORTED`, `FILE_READ`, `CAMERA_PERMISSION`, `SCANNER_UNAVAILABLE`, `IMAGE_PROCESS`, `STORAGE`, `SHARE`, `UNKNOWN`.
- **Error classes:** each `AppError` subclass sets `name` to its class name and calls `Object.setPrototypeOf(this, new.target.prototype)` so `instanceof` works under Hermes. `cause` is kept.
- **Imports:** `src/errors/AppError.ts` and `messages.ts` must not import React or React Native. Relative imports only.
- **Copy placement:** all copy lives in `src/i18n/` (the part-2 guard test enforces this). Remove table keys that become unused, from both tables.
- **Version:** 1.5.0, `android.versionCode` 5, `ios.buildNumber` "5".
- **Checks:** `npm test` and `npm run typecheck` pass at the end of every task.
- **Do not touch:** `.gitignore`, `.claude/`, `docs/claude-memory/`, `requirement/`, `New folder/`, `ios/`, `android/`.

## Review Focus

1. **A non-`AppError` thrown deep inside a workflow** (a bug or a native exception). Expected: an `UNKNOWN` popup with the code line, never a raw message or no popup at all. Pinned in Task 1 (`toAppError`) and Task 3 (one screen test per screen with a plain `Error`).
2. **Merge with one encrypted and one corrupt PDF.** Expected: the good files load, and one popup lists both files with their short reasons. The title and code are those of the first failure. Pinned in Task 3.
3. **Incoming where every shared file is rejected.** Expected: the per-file popup replaces "Không có file PDF hoặc ảnh hợp lệ", then the app goes home. There must not be two back-to-back alerts. Pinned in Task 3.
4. **Scanner error text localized by the OS** (not matching the permission or unavailable patterns). Expected: the `UNKNOWN` content with the `Mở Cài đặt` / `Đóng` buttons, as in today's hint. Pinned in Task 3.
5. **The library write fails on rename or delete.** Expected: a `STORAGE` popup with nothing changed in the library list. Pinned in Task 2 (`StorageError` thrown) and Task 3 (index screen).

**Interfaces:**
- Produces:
  - `type ErrorCode`
  - `class AppError extends Error { readonly code: ErrorCode; readonly fileName?: string; constructor(code: ErrorCode, opts?: { fileName?: string; cause?: unknown; message?: string }) }`
  - Subclasses: `PdfLoadError` and `PdfEncryptedError` take `(opts?: { index?: number; fileName?: string; cause?: unknown })` and expose `readonly index?: number`. `FileTooLargeError`, `UnsupportedFileError`, `FileReadError`, `CameraPermissionError`, `ScannerUnavailableError`, `ImageProcessError`, `StorageError`, `ShareError` and `UnknownError` take `(opts?: { fileName?: string; cause?: unknown })`.
  - `toAppError(e: unknown): AppError`: an `AppError` is returned as is; an error whose `name === 'EncryptedPDFError'` becomes `PdfEncryptedError({ cause })`, matched by name so `AppError.ts` stays free of the pdf library; anything else becomes `UnknownError({ cause })`.
  - `errorContent(err: AppError, t: Strings): { title: string; message: string; code: ErrorCode }`
  - `errorsContent(errs: AppError[], t: Strings): { title; message; code }`. With several errors, the message has one line per file: `${fileName || t.common.untitled} — ${t.errors.reason[code] ?? t.errors[code].title}`.
  - `useErrorAlert(): (err: unknown, opts?: { buttons?: AlertButton[] }) => void`. It accepts a single error or an array. It calls `Alert.alert(title, message + '\n\n' + t.errors.codeLine(code), opts?.buttons)`; an empty array is a no-op.
