# iScanner — Internationalization (Tiếng Việt / English) — Design Spec

- **Date:** 2026-10-07
- **Source:** requirement "07/10/2026 - sequence 2", part 2 of 5 ("Chức năng i18n, chuyển ứng dụng qua đa ngôn ngữ, tạm thời gồm 2 ngôn ngữ là english và tiếng việt").
- **Status:** Approved in chat; awaiting written-spec review.
- **Follow-ups that build on this:**
  - part 3: typed errors with localized popups, e.g. `PdfLoadError` → "Không load được file, vui lòng kiểm tra lại định dạng file PDF." / "Cannot load file, check your document's format file PDF.";
  - part 5: force update.

## 1. Goal and decisions

All user-facing text is available in Vietnamese and English, and more languages can be added later by adding one file.

| Topic | Decision |
|---|---|
| Language choice | The default is the device language: a Vietnamese device gets `vi`, anything else gets `en`. The user can override it with `Theo hệ thống` / `Tiếng Việt` / `English`, and the choice persists. |
| Where to choose | A new **Settings screen** (`app/settings.tsx`), opened by the ⚙︎ button in the library header. It has two groups, Appearance (theme) and Language, with three rows each and a `✓` on the current row. It replaces the ⚙︎ theme menu. |
| Mechanism | A small in-house module of typed string tables: `en` has the type `typeof vi`, so a missing or mistyped key is a **typecheck error**. Device language comes from `expo-localization` (new Expo native module, installed with `npx expo install`). No i18n JS library. |
| Storage | `settings.json` holds both settings, e.g. `{"theme":"dark","language":"en"}`. Saving one keeps the others. |
| Native strings | The iOS camera permission text is localized through app.json `locales`. Per-app language is declared through the `expo-localization` plugin `supportedLocales`, so Android 13+ and iOS list iScanner in system language settings. The app name `iScanner` is unchanged. |
| Not translated | Saved document names, and developer-only `console.*` text (part 4 handles logs). |
| Version | 1.4.0, Android `versionCode` 4, iOS `buildNumber` "4". |

Out of scope:
- right-to-left languages;
- a third language;
- translating error copy beyond moving the current messages into the tables (part 3 rewrites the error copy).

## 2. Modules

### 2.1 `src/i18n/vi.ts`, `src/i18n/en.ts` (pure data)

```ts
export const vi = {
  common: { cancel: 'Huỷ', ok: 'OK', ... },
  library: { ... }, scan: { ... }, merge: { ... }, incoming: { ... },
  viewer: { ... }, editor: { ... }, settings: { ... }, errors: { ... },
  format: { scanPrefix: 'Scan', mergePrefix: 'Gộp', pages: (n: number) => `${n} trang`, dateOrder: 'dmy' },
};
export type Strings = typeof vi;
// en.ts
export const en: Strings = { ..., format: { scanPrefix: 'Scan', mergePrefix: 'Merge', pages: (n) => (n === 1 ? '1 page' : `${n} pages`), dateOrder: 'mdy' } };
```

- Strings with parameters are functions.
- The Vietnamese values are the exact current copy, so nothing a user sees in Vietnamese changes.
- English copy is written to the same meaning.
- Language names are always shown in their own language (`Tiếng Việt`, `English`) in both tables.

### 2.2 `src/i18n/language.ts` (pure)

```ts
export type Language = 'vi' | 'en';
export type LanguagePreference = 'system' | Language;
export function resolveLanguage(pref: LanguagePreference, deviceLanguageCode: string | null | undefined): Language;
// pref 'vi' | 'en' → itself; 'system' → 'vi' when the device code starts with 'vi', else 'en'
export function stringsFor(lang: Language): Strings;
```

### 2.3 `src/settings/settings.ts` (replaces `src/theme/preference.ts`)

```ts
export type Settings = { theme: ThemePreference; language: LanguagePreference };
export function parseSettings(json: string | null): Settings;   // each field invalid or missing → 'system'
export function loadSettings(fs?: FsAdapter): Promise<Settings>; // never throws
export function saveSettings(patch: Partial<Settings>, fs?: FsAdapter): Promise<void>; // read-merge-write; may reject
```

- `ThemeContext` switches to `loadSettings` / `saveSettings({ theme })`.
- `toNativeScheme` and `ThemePreference` move with it or stay exported from the theme module.
- Existing `settings.json` files (`{"theme":"dark"}`) keep working.
- Two quick saves of different keys must not drop each other: saves are serialized through a module-level promise chain.

### 2.4 `src/i18n/LocaleContext.tsx`

- `LocaleProvider({ children, fs? })`:
  - loads `language` from settings;
  - reads the device language from `useLocales()[0]?.languageCode`, which updates live on Android and on the next foreground on iOS;
  - resolves the effective language.
- `useT(): Strings & { $: { language: Language; preference: LanguagePreference; setPreference(p): void } }`, or an equivalent shape such as `useLocale()` returning `{ t, language, preference, setPreference }`. The plan fixes the exact shape.
- Outside a provider it returns Vietnamese with preference `system` and a no-op setter, so the existing screen tests keep their Vietnamese assertions.
- `setPreference`:
  1. updates state immediately;
  2. persists through `saveSettings({ language })`;
  3. swallows a save failure.

### 2.5 `src/utils/format.ts` (changed)

- `formatDate(iso, strings)`: `vi` → `dd/MM/yyyy HH:mm` (unchanged); `en` → `MM/dd/yyyy HH:mm`.
- `defaultName(kind, date, strings)`: the prefix comes from `strings.format`, e.g. `Scan 05-10-2026 14.03` / `Gộp …` / `Merge …`. The date part is unchanged in both languages.
- `formatSize` is unchanged.

### 2.6 Settings screen and navigation

- `app/settings.tsx` (title `Cài đặt` / `Settings`):
  - section headers `Giao diện` / `Appearance` and `Ngôn ngữ` / `Language`;
  - rows `Theo hệ thống` / `System default`, `Sáng` / `Light`, `Tối` / `Dark`, and `Tiếng Việt`, `English`;
  - the selected row shows `✓`, `accessibilityRole="button"` and `accessibilityState={{ selected }}`;
  - themed with `useTheme()`.
- `app/_layout.tsx`:
  - adds `<LocaleProvider>` (inside `ThemeProvider`);
  - screen titles come from the strings;
  - the index `headerRight` is a ⚙︎ button (`accessibilityLabel` = `t.settings.title`) that pushes `/settings`.
- `ThemeMenuButton` and its test are removed. `ActionMenu` stays, because the document long-press menu uses it.

### 2.7 Native config (`app.json`)

- `locales`: `{ "vi": "./locales/vi.json", "en": "./locales/en.json" }`, each with `ios.NSCameraUsageDescription`.
  - vi: the current text `Ứng dụng cần quyền camera để scan tài liệu.`
  - en: `iScanner needs camera access to scan documents.`
- The scanner plugin's `cameraPermission` stays as the base (Vietnamese) value.
- `ios.infoPlist.CFBundleAllowMixedLocalizations: true`.
- Plugin `["expo-localization", { "supportedLocales": { "ios": ["vi", "en"], "android": ["vi", "en"] } }]`.

## 3. Migrating the strings

- About 80 literals in 15 files move into the tables: `index`, `scan`, `merge`, `incoming`, `viewer/[id]`, `_layout`, `PageEditor`, `CornerHandles`, `DocumentActions`/`ActionMenu`, `NameInput`, `DocumentRow`, `displayName`, `format`.
- `Alert.alert` and `ActionSheetIOS` options also come from the strings.
- `src/share/displayName.ts`'s fallback `Tài liệu` becomes a parameter, or callers pass `t.common.untitled`, so that `src/` modules stay free of React.
- **Guard test:** a test scans `app/**/*.tsx` and `src/components/**/*.tsx` for string literals containing Vietnamese letters (characters with diacritics, or `đ`) and fails on any match. `src/i18n/` and explicit allowlisted lines are excluded.

## 4. Error handling and edge cases

| Situation | Behavior |
|---|---|
| `settings.json` missing, invalid or holding an unknown language | Language `system`. |
| Device language unknown (`useLocales()` empty or `null` code) | `en`, unless the user chose `vi`. |
| Language save fails | The choice applies for the session only, silently. |
| Theme and language saved back-to-back | Both persist (saves are serialized). |
| Device language changes while in `system` | Android re-renders live; iOS picks it up on the next foreground. |
| Device language changes while `vi`/`en` is chosen | Ignored. |

## 5. Testing

- **Unit:**
  - `resolveLanguage` for each preference × device code (`vi`, `vi-VN`, `en-US`, `fr`, `null`, `undefined`);
  - `parseSettings` (old theme-only file, both keys, garbage, unknown values);
  - `saveSettings` keeps other keys and serializes concurrent saves;
  - `formatDate` and `defaultName` in both languages;
  - `en.format.pages(1) === '1 page'` and `pages(2) === '2 pages'`.
- **Components and screens** (RNTL v14, awaited):
  - `LocaleProvider` with a mocked `useLocales` returning `en`: the library shows `Scan document` / `Merge PDF`;
  - with `vi`: today's copy;
  - Settings screen: choosing `English` switches the copy at once and saves `{"language":"en"}` without losing `theme`; choosing `Tối` calls `Appearance.setColorScheme('dark')`;
  - the ⚙︎ header button pushes `/settings`;
  - the existing screen tests still pass unchanged in Vietnamese.
- **Guard test:** no Vietnamese literals in UI code.
- **Android emulator:**
  - switch the language in the app;
  - in `system` mode, change the device language (`adb shell cmd locale set-app-locales` / device settings) and see the app follow;
  - iScanner appears in Android 13+ per-app language settings;
  - the choice survives a restart.
- **iOS:** `expo config --type introspect` shows the localized camera usage text and `CFBundleAllowMixedLocalizations`. A real-iPhone check is left to the user.

## 6. Success criteria

1. Every visible string, alert and action sheet is in the chosen language. The default follows the device; the override persists.
2. Adding a language means one new table plus one union member, and typecheck lists anything missing.
3. Vietnamese copy is unchanged from 1.3.0.
4. All tests (including the guard) and typecheck pass, and the Android flows are verified on the emulator.
