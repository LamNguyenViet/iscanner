## What was built

- **`src/errors/AppError.ts`**
  - The base `AppError(code, { fileName?, cause?, message? })` and 11 subclasses: `PdfLoadError`, `PdfEncryptedError` (both carry `index`), `FileTooLargeError`, `UnsupportedFileError`, `FileReadError`, `CameraPermissionError`, `ScannerUnavailableError`, `ImageProcessError`, `StorageError`, `ShareError`, `UnknownError`.
  - `toAppError(e)`: an AppError passes through; `EncryptedPDFError` is matched by name or `constructor.name`; anything else becomes `UnknownError` with the original as `cause`.
  - `withFileName(err, name)` attaches a file name to an error that lacks one.
- **`src/errors/messages.ts`** has `errorContent` and `errorsContent`:
  - one error with a file name → `<file>\n<full message>`;
  - two or more errors → one line per file, `<file> — <short reason>`, using the first error's title and code;
  - an error without a file name → the plain message.
- **`src/errors/useErrorAlert.ts`** provides `showError(err | err[], { buttons? })`, which appends `Mã lỗi: CODE` / `Error code: CODE`. This is **the single display point** where part 4 hooks in logging.
- **Producers:**
  - `mergePdfs.loadPdf` guards load plus page count and indices. `EncryptedPDFError` is caught by `instanceof` (minifier-safe) and becomes `PdfEncryptedError`; everything else becomes `PdfLoadError`. A `copyPages` failure also becomes `PdfLoadError`.
  - `loadPickedPdfs` returns `failed: AppError[]`, always with a file name.
  - `importIncoming` returns `skipped: AppError[]`.
  - The scanner maps errors to `CameraPermissionError` or `ScannerUnavailableError`.
  - `libraryStore` add, rename and remove throw `StorageError`. Deleting the file after the index is written is best-effort.
  - `shareDocument` throws `ShareError`. `detectImageType` throws `ImageProcessError`.
- **Screens:** every error alert goes through `showError`. Only the delete confirmation and the incoming "nothing usable" notice remain as non-error alerts. The old error keys were removed from both language tables.
  - Scan, camera permission: `Mở Cài đặt` / `Huỷ`.
  - Scan, scanner unavailable: a single `Đóng`.
  - Scan, unrecognised scanner error: UNKNOWN content with `Mở Cài đặt` / `Đóng`.
  - Incoming: one popup for every rejection path.
- **Tests:** 503 (50 suites). Typecheck is clean.

## Rulings
- **T1, encrypted-PDF detection.** The `/encrypted/i` message fallback was dropped from `toAppError`, because it could mislabel unrelated errors. Minifier safety comes from the `instanceof` check in `loadPdf` instead.
- **T4 controller-executed.** Task 4 (device verification and docs) was done by the controller.
- **Final review #1 (Critical): one failed file.** The plan said to show a single failed file as a one-line list, which contradicts the spec, because the required sentence would never appear. The spec won: a single file shows `<file>\n<full sentence>`.
- **Final review #5 included.** The scan screen no longer double-wraps an AppError inside `UnknownError`.
- **Device bug, extra fix round (user-approved).** On Hermes, a corrupt PDF loads lazily and only fails at `getPageCount`, which showed UNKNOWN without the file name. Load plus page count are now guarded together, and the merge flow always keeps the file name.
