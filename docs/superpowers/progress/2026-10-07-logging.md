## What was built

- **`src/logging/redact.ts`** is pure. It redacts:
  - typed arrays, `ArrayBuffer`, `DataView` and `Buffer` → `[binary N bytes]`;
  - data URIs anywhere in a string, in any case, including line-wrapped ones → `[data-uri <mime>, N chars]`;
  - whole-string base64, plus embedded, URL-safe or whitespace-wrapped base64 runs of 200+ characters → `[base64 N chars]`.

  It also limits size:
  - other strings longer than 2,000 characters are truncated;
  - nesting deeper than 5 levels becomes `[depth]`;
  - arrays longer than 50 and objects with more than 50 keys are capped, and keys themselves are redacted;
  - circular references become `[circular]`.

  `Error` objects are serialized as `{name, message, code, fileName, stack ≤ 20 lines, cause ≤ 3 levels}`. All scans run in linear time.
- **`src/logging/format.ts`** has `localIsoTimestamp`, `logFileName` (local date), `formatRecord` (redacts and never throws) and `serializeError`.
- **`src/logging/retention.ts`** has `expiredLogFiles` (keeps today and the 6 previous days, ignores names that are not `YYYY-MM-DD.log`, keeps files dated in the future) and `isLogFileName`.
- **`src/logging/logger.ts`** provides `createLogger` and a lazy `log` singleton. The singleton loads `expoFs` only on first use.
  - Records are buffered and flushed every 2 seconds. `error` and `fatal` flush immediately.
  - Flushes run one after another. Each record's file name is fixed when it is queued, so records go to the correct day's file across midnight.
  - The buffer is capped at 500 records, with an overflow `warn`.
  - Each day's file is capped at 2 MB of UTF-8, measured with `fs.size`. If measuring fails, the size is treated as 0.
  - `debug` goes only to the dev console. The logger never throws.
- **`src/logging/globalHandlers.ts`**: an uncaught JS error is logged as `fatal`, flushed (waiting at most 500 ms), and then handed to the previous handler. Hermes unhandled promise rejections are logged as `UNHANDLED_REJECTION`.
- **`FsAdapter`** gains `list`, `append` and `size`, implemented with expo-file-system SDK 57 `Directory#list`, `File#write({append:true})` and `File#size`.
- **Wiring:**
  - `app/_layout.tsx` (`useAppLogging`) runs `log.init` (retention, app and OS metadata), logs `app.start {language, theme}` once both are loaded (`ThemeProvider` now exposes `loaded`), installs the handlers once, and flushes on background or inactive.
  - `useErrorAlert` logs every error it shows.
  - Warnings replace the old silent catches and `console.warn` calls.
  - Events: `scan.pdfCreated/cancelled`, `merge.created`, `share.received`, `incoming.saved`, `document.renamed/deleted/shared` (from the library and the viewer), `settings.theme/language`, `logs.exported`.
  - `[normalizePage]` and `[detectQuad]` are now `log.debug`.
  - A guard test forbids `console.*` outside `src/logging/`.
- **Export:** Settings → `Hỗ trợ` / `Support` → `Gửi log lỗi` / `Send error logs`.
  - `exportLogs` flushes, then joins the kept logs into `cache/iScanner-logs-<date>.txt` with a header line. A file that can't be read becomes `[unreadable: <name>]` instead of failing the export.
  - `shareLogFile` shares it as `text/plain` (`public.plain-text` on iOS).
  - With no logs, the screen shows `Chưa có log nào.`. Failures go through `showError`.
- **Tests:** 576 across 59 suites. Typecheck is clean. A global jest mock of `log` sits in `jest.setup.js`; `createLogger` stays real.

## Rulings
- **T1: redaction goes beyond the spec.** The spec's patterns could be bypassed: embedded, URL-safe or wrapped base64, data URIs that are upper-case or embedded, and base64 hidden in object keys. They were hardened to meet the spec's intent. Cost: some long non-base64 tokens get masked.
- **T1: one leak is accepted.** The unpadded last line of a wrapped data URI stays in the log if it is shorter than 16 characters (at most 15 characters).
- **T3:** the viewer's share button also logs `document.shared`.
- **T5:** done by the controller.
- **Final review #1:** a failure while measuring the day's file dropped every record that day. The size now comes from `fs.size` (bytes), falling back to 0 on failure. Export also continues past an unreadable file.

## Deferred minors
- **Redaction (T1):**
  - duck-typed errors lose their `message` and `name`;
  - `SharedArrayBuffer` is not labelled as binary;
  - `Map` and `Set` collapse to `{}`;
  - base64 split into groups of about 10 characters is not caught;
  - long path segments are over-redacted;
  - a 4-million-character string takes about 768 ms to scan;
  - redacted keys can collide;
  - a token of 16+ characters right after a data URI is absorbed into its marker;
  - a data URI wrapped every ~10 characters is not detected.
- **Logger (T2):**
  - no test for overlapping flushes;
  - an error can be evicted if 500 records are logged synchronously before its flush;
  - Hermes rejection tracking replaces React Native's dev tracker;
  - edge cases in uninstall;
  - `dontMock` is not in a `finally`.
- **Wiring (T3):**
  - warn noise: `deleteFiles` warns about files already gone, `sharedPayloads` warns on every return to the foreground, and `loadSettings` warns twice;
  - a refresh failure after a rename is logged both as a warn and as an error;
  - the layout uninstall is untested;
  - empty `afterEach` blocks.
- **Export (T4):**
  - the `logs.exported` `bytes` field counts characters;
  - the whole export is one string of up to 14 MB;
  - the double-press guard reads state from the render closure;
  - the exported `.txt` stays in the cache;
  - the "disabled while working" test is fragile.
- **Final review:**
  - an iOS disk-full append may raise an uncatchable Objective-C exception (upstream);
  - retention only runs at app start;
  - errors before `init` lack app and OS metadata, and errors before `LocaleProvider` loads are not caught;
  - the Hermes tracker is installed without `onHandled`, so late-handled rejections become false positives;
  - no integration test checks that a `showError` call produces a redacted line in the file;
  - the dev console `debug` output is not redacted.
