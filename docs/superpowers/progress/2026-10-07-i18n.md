## What was built
- **`src/settings/settings.ts`** replaces `src/theme/preference.ts`.
  - `settings.json` holds `{theme, language}`.
  - `saveSettings(patch)` is a serialized read-merge-write, so concurrent theme and language saves both persist.
  - `parseSettings` turns each bad or missing field into `system`; an old `{"theme":…}` file still works.
- **`src/i18n/`**
  - `vi.ts` holds the exact 1.3.0 copy. `en.ts` is typed `Strings = typeof vi`, so a missing key fails typecheck.
  - `language.ts` has `resolveLanguage`: `vi*` → vi, anything else → en. It also has `stringsFor`.
  - `LocaleContext.tsx` has `LocaleProvider` and `useLocale() → { t, language, preference, setPreference }`. It reads the device language from `expo-localization`'s `useLocales()` and renders nothing until the saved settings load, so there is no wrong-language frame or stale `t`. Outside a provider it returns `vi`.
- **`app/settings.tsx`**: the Settings screen, with Appearance and Language groups, 3 rows each and a `✓`. The ⚙︎ header button on the library screen pushes it. `ThemeMenuButton` was removed; `ActionMenu` is kept for the document menu.
- **Translated:** about 80 strings across every screen and component, including alerts, action sheets, accessibility labels, layout option labels, `formatDate` (vi `dd/MM`, en `MM/dd`), the `defaultName` prefix (`Scan`, `Gộp` / `Merge`) and `pages(n)` with English plurals.
  - `displayNameFromUri` returns `''`. Screens show and save `t.common.untitled` (`Tài liệu` / `Document`).
  - The incoming screen shows exactly the name it will save, without `.pdf`.
- **`app.json`**
  - `locales` with vi and en (`NSCameraUsageDescription`) and `CFBundleAllowMixedLocalizations`.
  - The `expo-localization` plugin with `supportedLocales` vi and en (Android `locales_config.xml`, iOS per-app language) and `allowDynamicLocaleChangesAndroid: true`. Prebuild adds `locale` to `configChanges`, so the activity is not recreated.
- **Guard:**
  - `__tests__/i18n/noHardcodedVietnamese.test.ts`, using the `vietnameseGuard.ts` helper, flags any line in `app/` or `src/` (except `src/i18n/`) that has a Vietnamese letter outside a comment, JSX text included.
  - `__tests__/appConfig.test.ts` guards the plugin options.
- **Tests:** 433, all passing; typecheck is clean.

## Device verification (release APK on the `iscanner_pixel` emulator, device language en-US, 2026-10-07): PASS
- First launch with `Theo hệ thống`: the app is in English (`Settings` button, `10/07/2026 15:38 · 2 pages`).
- ⚙︎ opens Settings, where the Appearance and Language groups are shown with a `✓`. The theme `Light` saved under 1.3.0 is still honored.
- Choosing `Tiếng Việt` switches the UI live (`Cài đặt`, `GIAO DIỆN`, `05/10/2026 … 9 trang`).
- After force-stop and relaunch the app is still Vietnamese. The long-press menu shows `Đổi tên/Chia sẻ/Xoá/Huỷ`, and the Xoá alert reads `Xoá tài liệu này?` with `XOÁ/HUỶ`.
- With language set to `Theo hệ thống`, `adb shell cmd locale set-app-locales com.dlbk.iscanner --locales vi-VN` switches the app to Vietnamese **live with the same PID (no restart)**, and `en-US` switches it back. The app locale was then reset to `[]`.
- **Not exercised on the device:** scan (camera), the share intent and merge in English. They are covered by English screen tests.

## Deferred minors
- A transient settings read error could reset the other field on the next save.
- No test checks that saving the theme keeps an existing language.
- The save queue is shared across `fs` instances (only matters in tests).
- The failed-save test does not assert the absence of an unhandled rejection.
- The `dateOrder` cast has no comment.
- The guard's quote tracking does not reset per line, so an apostrophe in JSX text can flip the string state; this only causes false positives.
- English test gaps: the scan failure alerts, `pickFailed`/`createFailed` in merge, `readFailed` in incoming, and `failed` in PageEditor.
- `libraryStore` hard-codes `vi` in an empty-name fallback that no path reaches.
- There is no `SplashScreen.preventAutoHideAsync`, so a one-frame blank screen is possible before settings load.
- An intermittent VirtualizedList `act()` console.error in full test runs (pre-existing).
- Cosmetic: the `group()` helper in `settings.tsx`, a stray blank line in a test, and `showError` rebuilt on each render.
