## What was built
- `src/theme/palette.ts`: light and dark palettes with 11 tokens (see the spec §2.1 table).
- `src/theme/preference.ts`: `settings.json` (`{"theme": ...}`) through `FsAdapter`/`expoFs`. A bad or missing file means `system`.
- `src/theme/ThemeContext.tsx`:
  - `ThemeProvider` calls `Appearance.setColorScheme('light' | 'dark' | 'unspecified')`, which overrides the native scheme app-wide.
  - `useTheme()` returns `{ colors, scheme, preference, setPreference }`. Outside a provider it returns the light defaults, so old screen tests stay unchanged.
- `app/_layout.tsx`: our `ThemeProvider` wraps the navigation `ThemeProvider` from expo-router (palette-overridden `DarkTheme`/`DefaultTheme`), together with `StatusBar style="auto"` and the index `headerRight` ⚙︎ (`ThemeMenuButton`).
- `src/components/ActionMenu.tsx`: a generic Android menu. `DocumentActions` is now a wrapper over it. `ThemeMenuButton` uses `ActionSheetIOS` on iOS and `ActionMenu` elsewhere.
- Themed: `index`, `scan`, `merge`, `incoming`, `viewer/[id]` (including the PDF view background), `DocumentRow`, `NameInput`, `SegmentedControl`.
  - Pattern: layout stays in `StyleSheet.create`; colors come from `makeStyles(colors)`, memoized with `useMemo`.
  - Unchanged by design: `PageEditor`, `CornerHandles`, `PagePreview`, and the scan processing overlay.
- `app.json`: `userInterfaceStyle: "automatic"`, plus `expo-system-ui` (installed; prebuild applies it automatically).
- Test helper: `__tests__/fixtures/theme.tsx` (`themed`, `settleTheme`, `styleOf`). To test dark mode, mock `react-native/Libraries/Utilities/useColorScheme`.
